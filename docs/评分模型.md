# 评分模型

这份文档只讲一件事：每条委托卡片上的分数是怎么算出来的，以及每个数字为什么取这个值。

## 输入

**委托字段**（批量导入时按竖线分隔，共 14 段）：

活动类型、区域、开始时间、结束时间、连续天数、单场时长（小时）、名额上限、已报名人数、参与要求（面试 / 技能 / 早起 / 体力 / 着装）、PU 学分类型、PU 学分数、志愿时长、是否有证书、是否有物资。

**个人档案**：

七天 × 三段（上午 / 下午 / 晚上）的空档表、最缺的学分类型、四条偏好（证书优先 / 就近优先 / 社交 / 轻松）、各区域单程通勤分钟、已累计的 PU 学分。

## 四项加权

```
总分 = 收益 V × 0.40 + 诉求匹配 M × 0.25 + 成本效率 E × 0.25 + 名额宽松 C × 0.10
```

权重是人为定的：收益最重要，因为它直接对应"我为什么要去"；匹配度次之，用来表达"这条对别人可能更好，对我未必"；成本效率再次之，用来劝退那些时间上不划算的；名额只是轻微影响，因为报名人数是会变的。

### 收益 V

```
pt = 40 × PU学分 × puW + 6 × 志愿时长 + 证书 18 + 物资 8
V  = clamp(pt × 100 / 95, 0, 100)
```

- `puW`：命中个人档案里最缺的学分类型取 2.2，其余取 1.2。同一条委托对不同人值多少分，体现的就是这个系数。
- 志愿时长按每小时 6 分计，证书固定 18 分，物资固定 8 分。
- 偏好加成：勾选「证书优先」且该委托发证书 +8；勾选「就近优先」且单程 ≤ 12 分钟 +6。
- 归一化分母 95 是按示例数据里“收益接近上限”的那条委托定的量级。它不是理论最大值，只是一个把长尾压回 0–100 的刻度。

### 成本效率 E

```
costH = 单场时长 × 连续天数 + prep + 往返通勤
prep  = 需要培训 ? 1 : 0 小时 + 需要面试 ? 0.75 : 0 小时
往返通勤 = 单程分钟 × 2 / 60
E = clamp(100 − costH / 16 × 100, 0, 100)
```

准备时长是二值的：参加培训就算 1 小时，要面试就算 0.75 小时，不细分流程。

分母 16 表示"一天里还能支配的清醒时间"的量级：成本到 16 小时，效率归零。这个数改过一次，见 `CHANGELOG.md`。

### 名额宽松 C

```
C = clamp((1 − 已报名 / 上限) × 100, 0, 100)
```

名额已满时 C = 0，还有名额时越空越高。上限为 0 的委托按 0 处理，不做除零。

### 诉求匹配 M

以 45 为基准分，逐项加减：

| 条件 | 调整 |
|---|---|
| 命中个人最缺的学分类型 | +13 |
| 与本人所在区域相同 | +10 |
| 线上活动 | +8 |
| 在市区，跨区通勤 | −8 |
| 年级或专业与参与资格不符 | −32 |
| 偏好「社交」且是多人的文体活动 | +6 |
| 偏好「轻松」且无体力要求 | +8 |

资格不符的惩罚故意做得重：分数再高也没法去，必须让它在列表里沉下去。

## 难度 D

难度从 16 起累加，封顶 100：

| 项 | 加分 |
|---|---|
| 需要面试 | +18 |
| 需要专业技能 | +14 |
| 早起，或开始时间早于 08:00 | +10 |
| 需要体力 | +12 |
| 对着装有要求 | +4 |
| 每多一天连续参与 | +8 |
| 名额占用率 ≥ 90% | +10 |
| 单场时长 ≥ 6 小时 | +8 |

**D 不参与总分。** 它只作为卡片上的一行风险提示。

这是刻意分开的：难度描述"这条委托要付出什么"，收益描述"它能换来什么"。如果把难度加进总分，一条高难度高回报的委托会被自己的难度扣分，等于把两件事混成一件。分开之后，用户看到的是"这条很难，但很值"或"这条不难，但也不值"，判断权留给人。

## 时间修正

综合分算完后再乘一个系数，取决于这条委托和「我的日程」的关系：

| 情况 | 系数 |
|---|---|
| 与已有安排时间重叠（撞车） | × 0.45 |
| 与该时段的所有空档完全不重合 | × 0.62 |
| 与空档部分重合 | × 0.86 |
| 空档整段覆盖 | × 1 |

撞车的委托不会被删掉，只是降权并置灰，因为原有安排可能被取消。系数 0.45 是让撞车的委托落在“时间冲突”区间，而不是直接沉到 0。

## 档位

```
若撞车        → 「时间冲突」（标签固定，不再按分数分档）
否则 ≥ 75     → 「值得抢」
否则 ≥ 60     → 「可以一接」
否则 ≥ 45     → 「有空再说」
其余          → 「性价比低」
```

分档线取 75 / 60 / 45，对应 12 条示例委托的自然分布：大约三条值得抢、四条可以一接、其余分散在两档。

## 为什么是规则，不是模型

四个理由：

1. **可解释**。每个分数都能列出加分项和减分项，用户被问“为什么这条只有 50 分”时能当场答出来。
2. **可测试**。评分是纯函数，可以在没有浏览器的环境里用桩对象批量跑，12 条示例一次验证完。
3. **离线**。没有网络请求，没有模型调用，打开网页就能算。
4. **零成本**。不需要 key，不需要额度，不会因为服务不可用而白屏。

代价是要不断校准：改一个常数，就得回头看一眼 12 条示例的分布是否还合理。这是一个持续的手工活。
