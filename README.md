# 校园委托板 Campus Quest Board

把校园里的志愿、讲座、文体活动汇总成「委托」，并为每条委托给出一个**可解释**的性价比评分。

单文件网页应用：无构建步骤、无后端、无账号体系，双击即用。

## 运行

双击 `index.html`，用 Chrome / Edge / Firefox 打开即可。首次打开会自动生成 12 条示例委托，日期按打开当天动态推算。

无需安装任何依赖，也不需要启动本地服务。

## 四个视图

| 视图 | 作用 |
|---|---|
| 委托板 | 卡片列表 + 左侧筛选（类型、区域、时间），每条委托标注要求、奖赏、名额与 PU 学分 |
| 我的日程 | 时间轴 + 每日空档预算，看当天还能接多少 |
| 性价比分析 | 四维 KPI、三张图表与综合分榜单 |
| 个人档案 | 七天三段空档表、最缺的学分类型、偏好、各区域通勤分钟、PU 进度 |

## 评分模型

综合分由四项加权构成：

```
总分 = 收益 V(40%) + 诉求匹配 M(25%) + 成本效率 E(25%) + 名额宽松 C(10%)
```

- **收益 V**：`40 × PU 学分 × 加权系数 + 6 × 志愿时长 + 证书 18 + 物资 8`。
  加权系数由个人档案决定：最缺的学分类型 × 2.2，其余 × 1.2，整体再按 95 点归一。
- **成本效率 E**：先算总时长 `现场时长 × 连续天数 + 准备时长（培训 +1h / 面试 +0.75h）+ 往返通勤（2 × 单程分钟 / 60）`，再取 `100 − costH / 16 × 100`。
- **名额宽松 C**：`(1 − 已报名 / 上限) × 100`。
- **诉求匹配 M**：以 45 为基准，命中缺失的学分类型 +13，同区域 +10（线上 +8，市区 −8），参与资格与本人年级/专业不符 −32，再按偏好叠加。
- **难度指数 D**：从 16 起累加（面试 +18、需技能 +14、早起或 8 点前到场 +10、体力 +12、着装 +4、每多一天 +8、名额占用 ≥ 90% +10、时长 ≥ 6 小时 +8），封顶 100。**D 不进入综合分**，只作为委托卡上的风险提示。

收益里另有两条偏好加成：勾选「证书优先」且有证书 +8，勾选「就近优先」且单程 ≤ 12 分钟 +6。

**时间修正**：与已有安排撞车整体 × 0.45；空档完全不重合 × 0.62；部分重合 × 0.86。

**档位**：撞车时标签固定为「时间冲突」；否则 ≥ 75「值得抢」，≥ 60「可以一接」，≥ 45「有空再说」，其余「性价比低」。

## 数据

全部数据存在浏览器本地，键名 `campus-quest-board.v1`，不上传任何服务器。

应用内置三种数据操作：

- **导出 JSON**：把当前委托与个人档案导出为一份 JSON 备份
- **批量导入**：粘贴竖线分隔的 14 字段文本，一次录入多条委托
- **恢复示例数据**：清空改动，回到内置的 12 条委托

标记委托完成后，PU 学分自动计入进度，且可以撤销。

## 文件结构

```
index.html      全部内容：内联 CSS、原生 JS、评分与渲染逻辑
README.md       本文件
```

`index.html` 内部按职责分为三层：UI（视图渲染与事件）、CORE（评分、时间判定、归一化）、DATA（localStorage 读写与导入导出）。

## 外部资源

- 图表：ECharts 5.5.1，通过 jsDelivr CDN 引入
- 字体：Noto Serif SC / Noto Sans SC / IBM Plex Mono，通过 miaoda.feishu.cn 字体镜像引入

断网时图表区域会空白、字体回退到系统字体，委托列表、筛选与评分逻辑不受影响。

## 已知边界

- 没有账号体系与多端同步，数据随浏览器走
- 不代报名、不抓取真实活动，委托数据需自行录入或粘贴导入
- 评分基于「空档是否整段覆盖」的粗粒度判定，刻意不要求用户排出精确课表
